# ADR-0001: Module layout, toolchain and shared data

- Status: Accepted
- Date: 2026-09-25
- Deciders: Sanam Pakuwal

## Context

The Go port is one spoke of the NepDate family (hub ADR-0001). It must stay dependency-free and
give the same results as every other port.

## Decision

1. **One module at the repository root:** `github.com/sanamhub/nepdate-go`, package name
   `nepdate` (it doesn't match the path's last element, so every file says `package nepdate` and
   the README shows the import). The patro (tithi, public holidays and events) lives in the
   package `github.com/sanamhub/nepdate-go/patro` (package name `patro`, directory `patro/`), as
   hub ADR-0004 requires. `patro` imports `nepdate`; `nepdate` never imports `patro`.
   It is a package, not a second module: Go links only the packages a program imports, so a
   package already keeps the patro strings out of core-only binaries, while a nested module would
   need its own prefixed tags (`patro/vX.Y.Z`) and `replace` lines for no size gain. One tag
   releases both packages with the same version (ADR-0005).
2. **Toolchain:** `go 1.24` in `go.mod` (needed for `iter`, `encoding.TextAppender`, `b.Loop`). CI
   runs the two supported releases, Go 1.26 and 1.27. Since 1.27, `go test` vets that no newer
   standard-library symbol is used, so the `go` line stays honest.
3. **Zero dependencies** in the root module, tests included. Competitor benchmarks live in a
   separate module, `benchmarks/go.mod`, with a `replace` to `..`; GPL and unlicensed competitors
   never enter the library's `go.sum`.
4. **Shared data:** `shared/` is a read-only copy of the hub's `data/` and `spec/` with
   `shared/VERSION` (hub ADR-0001 §3). CI calls the hub's reusable `shared-check`; a weekly
   `shared-sync` opens a PR that also runs `go generate ./...`.
5. **Generator:** `internal/gen` (package `main`, standard library only) reads `shared/data/` and
   writes `calendar_gen.go` and `patro/patro_gen.go`, each starting with
   `// Code generated by internal/gen. DO NOT EDIT.` (the form tools recognise). `doc.go` holds
   `//go:generate go run ./internal/gen`. `go run ./internal/gen -check` generates in memory,
   compares the bytes with the files on disk and exits 1 on any difference without writing;
   the CI program runs it (ADR-0004 gate 4). It does not use `git diff`, so it gives the same
   answer with uncommitted work in the tree.
6. **Dev commands** are Go programs, not a Makefile, so Windows works without extra tools:
   `go run ./internal/ci` runs every gate (ADR-0004).

## Consequences

- `go get github.com/sanamhub/nepdate-go` adds nothing else to a user's `go.sum`.
- The generated files are ordinary Go source, readable in review.
- No JSON parsing and no `encoding/json` in users' binaries (ADR-0002 §3).
